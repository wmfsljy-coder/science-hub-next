# 3단계 설계 — 새 저장소를 원본으로, 옛 주소는 넘겨주기 (아직 실행하지 않음)

2026-11-08 작성. 1·2단계로 44단원 수업 화면·자료실·QR 모음·교사 화면이 모두 `science-hub-next` 안에서 돈다.
지금은 빌드할 때 옛 저장소 17개를 **읽어 와서** 복사한다. 3단계는 (1) 내용의 원본을 이 저장소로 옮기고 (2) 옛 주소를 새 주소로 넘겨준다.

## 1. 내용의 원본을 이 저장소로 옮기기

### 폴더
```
science-hub-next/
  units-src/
    _engine/            공용 엔진 한 벌(theme.js … qrcode.js, CSS) — 지금 public/engine/ 의 원본
    _hub/               허브 자료(review-*.js, unit-items-all.js, precheck-all.js, sections.js, share-config.js, plates.kml, resources 원자료)
    <저장소>/_repo/      저장소마다 다른 것(share-config.js, people-data.js)
    <저장소>/<단원>/     index.html + 자료 js + data/ + img/ + LESSON.md (지금 옛 저장소 폴더 그대로)
  tools/                옛 _tools 중 아직 쓰는 것(make_lessons.js, make_review_bank.js, make_unit_items.js, make_resource_list.py, check_ids.py, allcheck·quizrun·labrun·tabcheck…)
```
- `scripts/sync-units.mjs`·`sync-hub.mjs` 는 `CONTENT_DIR` 대신 `units-src/` 를 읽게 바꾼다. 단원 폴더 모양이 같아서 고칠 곳은 경로뿐이다. 엔진이 한 벌이 되므로 '12벌 비교' 코드는 지운다.
- 옮긴 뒤 단원 index.html 의 `../assets/` 는 그대로 두어도 된다(빌드가 바꿔 줌). 나중에 원본 자체를 `/science-hub-next/engine/` 로 바꿔도 된다.

### 옮기는 방법(권함: 단순 복사 + 기록 남기기)
1. 다른 작업자의 진행 중인 고침이 모두 푸시됐는지 확인(옛 저장소 17개 `git status` 깨끗, `main == origin/main`).
2. 옛 저장소마다 `git tag move-to-hub-next` (옮긴 시점 표시) 후 푸시.
3. `node scripts/phase3/import-content.mjs`(만들 것): 옛 저장소 폴더에서 단원 폴더·assets·허브 자료를 `units-src/` 로 복사하고, 각 저장소의 그 시점 커밋 해시를 `units-src/SOURCES.md` 에 적는다. 역사(커밋 기록)는 옛 저장소(보관)에 남는다.
   - 역사까지 합치고 싶으면 저장소마다 `git filter-repo --to-subdirectory-filter units-src/<저장소>` 한 사본을 만들어 `git merge --allow-unrelated-histories` — 17번 해야 해서 권하지 않음.
4. 빌드 결과 비교: 옮기기 전 `out/` 과 옮긴 뒤 `out/` 의 파일 목록·해시가 같아야 한다(다른 것은 `?v=` 해시가 붙은 엔진 주소뿐이어야 함). `check-units.mjs --all` 통과.
5. CLAUDE.md 규칙 4·5 바꾸기: "단원 내용은 이 저장소 `units-src/` 에서 고친다". 옛 저장소 README 맨 위에 "이 저장소는 보관용입니다. 고침은 science-hub-next 에서" 한 줄.
6. 다른 작업자(내용·엔진 담당)에게 새 위치를 알리고, 그 뒤로는 옛 저장소에 푸시하지 않기로 정한다(동시에 두 곳을 고치면 어긋남).

## 2. 옛 주소 넘겨주기

GitHub Pages 는 서버 쪽 301 넘겨주기가 없으므로 옛 저장소의 **index.html 만** '넘겨주기 한 장'으로 바꾼다. 스크립트: `scripts/phase3/make-redirects.mjs`(준비됨, 아직 안 돌림).

| 옛 주소 | 새 주소 |
|-|-|
| `/<저장소>/` (12) | `/science-hub-next/c/<저장소>/` |
| `/<저장소>/<단원>/` (44) | `/science-hub-next/u/<저장소>/<단원>/` |
| `/science-teacher-hub/` | `/science-hub-next/` |
| `/science-teacher-hub/class/` · `records/` · `resources/` · `qr/` · `maps/` | 같은 이름의 새 화면 |
| `/science-teacher-hub/phet/` | `/science-hub-next/resources/#PhET` |
| 껍데기 4개 `/integrated-science/` 등 | `/science-hub-next/` |

- 넘겨주기 페이지: `location.replace(새 주소 + location.search + location.hash)` → `?sec=02`, `?open=1`, `?all=1`, `#PhET` 가 그대로 간다(인쇄해 둔 소단원 QR·과목 QR 이 계속 동작). JS 가 꺼진 기기는 `<noscript><meta refresh>` 로 쿼리 없이 넘어가고, 본문에 링크도 있다. `canonical` 은 새 주소, `noindex`.
- `?all=1` 과목 QR: 옛 `/<저장소>/?all=1` → `/c/<저장소>/?all=1` → 새 과목 페이지가 학생 모드(교사 단추 숨김, sessionStorage `sth-all`)로 연다(2단계에서 만들어 둠).
- 학생 진도: 같은 출처라 그대로(1단계에서 확인). 로그인·우리 반은 같은 Apps Script.
- 자료 파일(js·img·data·assets)은 **지우지 않는다**. 이미 열려 있던 탭·캐시된 페이지가 깨지지 않게 한 학기 둔 뒤 저장소를 Archive.

### 순서(수업 없는 시간에, 약 30분)
1. 1번(원본 옮기기)이 끝나고 새 사이트 배포·`check-units.mjs --all` 통과 확인.
2. 옛 저장소마다 `git tag pre-redirect && git push --tags`.
3. `node scripts/phase3/make-redirects.mjs` (미리 보기) → 목록 확인(약 61쪽) → `--apply`.
4. 저장소마다 `git diff --stat`(index.html 만 바뀌었는지) → 커밋 "새 주소로 넘겨주기" → 푸시.
5. 확인: 옛 QR 몇 개(단원 전체, `?sec=02`, `?open=1`, 과목 `?all=1`)를 휴대폰으로 찍어 새 단원·소단원으로 가는지, 옛 허브 `class/` 가 새 교사 화면으로 가는지.
6. 학생·교사에게 "주소가 바뀌었지만 예전 QR 도 그대로 됩니다" 안내.

### 되돌리기
- 커밋 전: `node scripts/phase3/make-redirects.mjs --undo` (git checkout 으로 index.html 되살림).
- 푸시 뒤: 저장소마다 `git revert <넘겨주기 커밋>` 또는 `git checkout pre-redirect -- . && git commit -m "넘겨주기 되돌림" && git push`. Pages 가 1~2분 안에 옛 화면으로 돌아온다. 새 사이트는 그대로라 영향 없음.
- 1번(원본 옮기기)을 되돌릴 때: `units-src/` 를 지우고 sync 가 다시 `CONTENT_DIR` 을 읽게(커밋 하나 revert). 옛 저장소는 `move-to-hub-next` 태그 시점 그대로 남아 있다.

## 3. 남는 것·주의
- science-teacher-hub 의 `share-backend/`(Apps Script)는 넘겨주기 대상이 아니다(코드 저장소로 계속 씀). 보안 브랜치가 합쳐지면 `legacy/hub/` 를 지우거나 main 판과 맞춘다.
- 지도 Embed 키 리퍼러는 같은 호스트라 그대로 된다.
- 넘겨주기 뒤 1주일은 옛 저장소 Pages 접속 수(있으면)와 새 사이트 오류를 지켜본다.
